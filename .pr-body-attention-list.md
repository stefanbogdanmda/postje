# Owner Attention List

Replaces the bare user table at `/admin` with an Operator-Console attention list that surfaces — in urgency order — every post or client signal that needs your attention across all clients. The old user table moves to `/admin/users`.

## What's new

- `src/lib/admin/attention.ts` — aggregation queries (one per signal) plus a `getAttentionData(db, now)` combiner running them in parallel with `Promise.all`. No new tables; existing alert columns (`alertedAt`, `regenLimitAlertedAt`, `firstSeenAt`, `publishError`, `publishAt`, etc.) drive the page.
- `src/lib/admin/__tests__/attention.test.ts` — Vitest + PGlite, one `describe` per section + an integration test for the combiner (28 tests total).
- `src/app/admin/page.tsx` — replaced. Now the Attention List.
- `src/app/admin/users/page.tsx` — old user table moved here (with a defensive `limit(200)`).
- `src/app/admin/layout.tsx` — shared admin shell: auth guard + nav + operator-console CSS tokens.
- `src/components/admin/{attention-section,attention-item,calibration-item,admin-nav}.tsx` — presentational components.
- `src/styles/admin-tokens.css` — operator-console palette (sober near-white, severity colors as traffic-light only).

## Why

Spec [docs/superpowers/specs/2026-05-12-attention-list-design.md](docs/superpowers/specs/2026-05-12-attention-list-design.md) (Aesthetic Option A — Operator Console — locked).

The old `/admin` page was a raw users table — useful at zero clients, useless at five. We need one screen that answers "what fires need putting out before my 10am call." All the data was already stamped onto rows by the alert crons and the regen flow; this PR only adds the read path.

## Sections (in urgency order)

1. **Failed to publish** — `status='failed' OR publishError IS NOT NULL` (will populate once the publisher ships)
2. **Overdue** — approved, `publishAt < now`, not yet published
3. **Stale drafts** — `alertedAt IS NOT NULL` and still draft, sorted oldest-`firstSeenAt`-first
4. **Regen limit hit** — `regenLimitAlertedAt IS NOT NULL` and still draft
5. **Unseen drafts** — `status='draft' AND firstSeenAt IS NULL`
6. **Recent rejections** — rejected in the last 7 days
7. **Calibration** — clients created in the last 7 days, with their post count (client-anchored, distinct row shape)

Each item links to the relevant client view; no inline mutations on this page (approve/reject/cancel happen on the client's page).

## Aesthetic

Operator Console: Inter (Geist) for body, Geist Mono for counts and timestamps, near-white background, single-pixel borders, severity reserved for amber (warn) and red (critical). Density is high — the goal is "scan everything in one sitting", not "browse a dashboard". A small `src/styles/admin-tokens.css` defines the palette as CSS custom properties on `.admin-shell`; everything else is inline styles matching the existing admin pages.
